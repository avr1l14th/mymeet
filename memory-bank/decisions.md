# Decisions

## Формат записи
- Дата: `YYYY-MM-DD`
- Решение: кратко
- Почему: 1-2 причины
- Риск: что может пойти не так

## Журнал решений
- 2026-02-18
  - Решение: создать `memory-bank` как единый источник контекста проекта
  - Почему: уменьшает потери контекста между сессиями и ускоряет диагностику
  - Риск: устаревание записей без регулярного обновления
- 2026-02-18
  - Решение: строить цифровой двойник `mymeet.ai` поэтапно через ключевые экраны
  - Почему: проще контролировать качество и сохранять стабильность интерфейса
  - Риск: при отсутствии строгой фиксации этапов можно потерять целостность UX
- 2026-02-18
  - Решение: боковое меню и базовый каркас интерфейса считать неизменными по умолчанию
  - Почему: это снижает риск регрессий при добавлении новых разделов
  - Риск: слишком жесткий каркас может замедлить изменения, если не пересматривать его осознанно
- 2026-02-18
  - Решение: убрать хардкод навигации и использовать единый реестр экранов в `App`
  - Почему: новые экраны добавляются в одном месте и меньше риск поломок существующего поведения
  - Риск: при неверной конфигурации реестра экран может стать недоступным
- 2026-02-18
  - Решение: экран `Meetings` реализовать по Figma-узлу `27141:2899` с табами и вариативными строками списка
  - Почему: это закрывает этап 1 и выравнивает UI с целевым визуалом продукта
  - Риск: мок-данные могут отличаться от будущих реальных данных API
- 2026-02-19
  - Решение: добавить контрол `Фильтры` справа в строке табов на экране `Meetings`, используя паттерн с экрана `Search`
  - Почему: это выравнивает расположение контрола с актуальным Figma-узлом `27205:5851` и сохраняет единый UX между экранами
  - Риск: отдельный экран фильтров пока остается промежуточным шагом до возможного встраивания правой панели
- 2026-02-19
  - Решение: заменить переход на отдельный экран `filters` на единый popover-контрол по Figma-узлу `27161:8402` для экранов `Search` и `Meetings`
  - Почему: это соответствует дизайну (меню у кнопки `Фильтры`) и убирает разрыв поведения между двумя экранами
  - Риск: пункты `Источник/Авторы/Дата` пока отображаются как меню-уровень 1 без вложенных раскрытий
- 2026-02-19
  - Решение: для пункта `Источник` добавить hover-раскрытие финального popover-списка по Figma-узлу `27161:8460`
  - Почему: это точное поведение и компоновка из дизайна для этапа многоуровневой фильтрации
  - Риск: состояния выбора источников (checked/счетчик) пока не подключены к данным фильтрации
- 2026-02-19
  - Решение: подключить реальную фильтрацию по источникам как multi-select с единым состоянием для экранов `Поиск` и `Встречи`
  - Почему: это приводит поведение popover к Figma (`27205:7320`) и делает индикаторы (`чекбокс`, `точка`, бейдж `1`, `Очистить фильтры`) функциональными
  - Риск: старый экран `MeetingFiltersScreen` использовал одиночный source-фильтр и требовал совместимой адаптации под новый тип

- 2026-02-19
  - Решение: подготовить проект к GitHub Pages через GitHub Actions с `base: "/mymeet/"`
  - Почему: это безопасный и бесплатный способ публикации с автодеплоем на каждый push в `main`
  - Риск: без включения `Settings -> Pages -> Source: GitHub Actions` деплой не начнется

- 2026-02-19
  - Решение: для локальных SVG-иконок меню использовать относительные пути `icons/...` вместо абсолютных `/icons/...`
  - Почему: на GitHub Pages проект обслуживается из подпути `/mymeet/`, и абсолютные пути ломают загрузку ассетов
  - Риск: при переходе на вложенные клиентские маршруты без hash-router относительные пути могут потребовать отдельной проверки

- 2026-02-19
  - Решение: заменить источник иконки `Google Meet` на локальный SVG `public/icons/google-meet.svg`
  - Почему: удаленный ассет отображался растянутым; локальный SVG фиксирует корректные пропорции 14x14
  - Риск: при изменении имени файла потребуется синхронно обновить путь в `src/assets.ts`

- 2026-02-19
  - Решение: сохранять фоновую заливку у пункта `Источник/Авторы` первого уровня, пока открыт соответствующий подпоповер
  - Почему: это выравнивает поведение с Figma (одновременная подсветка открытого пункта уровня 1 и hover пункта уровня 2)
  - Риск: минимальный; добавлен только визуальный state-класс без изменения логики фильтрации
